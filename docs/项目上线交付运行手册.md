## 一、系统概述

- **系统名称**：学习支持与辅导协作智能体系统（Learning Support Agent）
- **核心功能**：学生制度问答（RAG+引用）、辅导预约（Agent 工具链+学生确认）、知识库管理、提示词热更新、对话审计与风险转人工
- **技术栈**：FastAPI + SQLite + FAISS/BM25 + OpenAI 兼容 LLM
- **人工确认/审核点（合规设计）**：① 学生确认预约/计划草稿后才生效；② 管理员审核知识库与系统提示词；③ 高风险对话（心理危机等）标记并转人工辅导

## 二、环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Linux（Ubuntu 20.04+）/ Windows 10+ / macOS |
| Python | 3.11+ |
| 内存 / 磁盘 | 4GB+ / 2GB+（含 FAISS 索引与数据库） |
| 网络 | 需访问 LLM API（未配置时系统降级为纯检索模式仍可用） |
| 依赖 | 见 requirements.txt（faiss-cpu、rank_bm25、jieba、openai、numpy、fastapi、uvicorn、pdfplumber） |

## 三、部署步骤（标准安装）

```bash
# 1. 获取代码
git clone https://github.com/Listening777/learning-support-agent.git
cd learning-support-agent

# 2. 安装依赖
pip install -r requirements.txt

# 3. 配置 LLM（可选；不配置则降级为纯检索模式）
cp .env.example .env
#   编辑 .env：LLM_BASE_URL / LLM_API_KEY / LLM_MODEL 三项

# 4. 初始化数据库与知识库（建 9 张表 + 演示账号 + 导入示例制度文档）
python scripts/init_db.py

# 5. 启动服务
python -m uvicorn learning_support.main:app --host 0.0.0.0 --port 8000 --app-dir src
```

**访问入口**：学生端 `http://（服务器IP）:8000/chat` ｜ 管理端 `http://（服务器IP）:8000/admin`
**演示账号**：管理员 admin / admin123；学生 student / 123456（上线前必须修改默认密码）。

## 五、日常运行操作

### 5.1 管理员日常

- **知识库维护**：制度更新后上传新文档并删除旧版本（列表删除按钮，自动重建索引）；
- **提示词调整**：修改后立即生效，误改可"恢复默认模板"；
- **审计巡检（建议每日）**：审计页查看红色 high 风险对话 → 按"转人工提示"联系对应学生；黄标 medium 对话每周汇总一次；
- **预约管理**：support_requests 表查看确认状态，线下取消按制度 24 小时规则操作。

### 5.2 运维日常

- **服务守护**：生产建议 `systemd` 托管（`ExecStart=python -m uvicorn learning_support.main:app --host 0.0.0.0 --port 8000 --app-dir src`，Restart=always）；
- **日志位置**：应用日志 stdout（systemd 收集至 journal）；工具轨迹在 agent_logs 表；
- **健康检查**：`curl http://127.0.0.1:8000/api/health` 返回 `{"code":0}`；
- **备份（每日）**：`cp data/app.db data/backup/app-$(date +%F).db`（保留 30 天）；FAISS 索引可由 doc_chunks 重建无需备份。

## 六、故障处理（异常兜底对照）

| 现象 | 系统行为 | 处理办法 |
|---|---|---|
| LLM 超时/不可用 | 前端显示"助手暂时不可用…"；或降级返回检索条文 | 检查 .env 供应商状态/余额；恢复后无需重启 |
| 检索异常（索引损坏） | 回答"制度检索暂时不可用，未找到依据" | 后台删除并重传文档，或重跑 `python scripts/init_db.py`（幂等） |
| 工具连续失败达 5 轮 | 返回"处理了几轮仍未完成，请换个说法或联系辅导老师" | 查 agent_logs 定位失败工具；多为 LLM 服务异常 |
| 学生反馈回答编造 | —— | 后台核对提示词模板是否被改动 → 恢复默认；核对制度文档是否缺失对应条文 |
| 4293 频繁请求 | 学生端提示稍后再试 | 属限流保护，1 分钟自动恢复；恶意刷可临时调低 RATE_LIMIT |
| 无法登录 | 4011 用户名或密码错误 | 核对账号；忘记密码由管理员重置（更新 users 表哈希） |

## 七、升级与回滚

1. **升级**：`git pull` → `pip install -r requirements.txt` → 重启服务；数据库新增表由启动时建表语句自动补齐（向后兼容，旧数据不受影响）；
2. **回滚**：`git log --oneline` 找到上一稳定版本 → `git checkout <commit>` → 重启；回滚后数据库仍可读写（新增表不破坏旧版本）；
3. **提示词误改回滚**：后台"恢复默认模板"一键生效；
4. **回滚后校验**：跑 /api/health + 学生端冒烟问答 + 对比 messages/support_requests 条数一致。

## 八、安全与合规运行要求

- 数据安全：学生对话保留一学年，到期脱敏归档（制度第十条）；审计页仅展示统计与风险片段；
- 内容安全：AI 不做心理疏导、不代写作业；风险转人工话术已内置，管理员须保证 risk_rules 中心理危机类规则常开；
- 权限：管理员账号专人专用；导出数据须走审批；
- 供应商合规：选用已备案的大模型服务；调用日志保留 6 个月以上。

## 一、方案总览

### 1.1 设计目标

将校内学习支持服务从纯人工流程改造为"AI 承接高频事务 + 真人负责复杂决策"的人机协作系统。设计遵循三条原则：

1. **合规优先**：所有有副作用的操作（预约、计划生效）必须经学生确认；敏感对话自动识别转人工；
2. **答案可溯源**：制度类回答一律引用出处，制度外明确答"未找到"，杜绝编造；
3. **供应商可替换**：LLM 通过 OpenAI 兼容协议调用，.env 三项配置即可切换供应商。

### 1.2 总体架构（四层）

```
┌─────────────────────────────────────────────────────────┐
│ 入口层：学生聊天页（SSE 流式） │ 管理后台（SSR 4页） │ REST API │
├─────────────────────────────────────────────────────────┤
│ 服务层：JWT认证 │ 会话管理 │ RAG管道 │ LLM封装 │ 审计服务      │
├─────────────────────────────────────────────────────────┤
│ 智能体层：5轮执行循环 │ 5个工具(Function Calling) │          │
│          三层顺序约束防线 │ 确认中断 │ agent_logs 日志        │
├─────────────────────────────────────────────────────────┤
│ 数据层：SQLite(9张表) │ FAISS 向量索引 │ BM25 关键词索引      │
└─────────────────────────────────────────────────────────┘
```

### 1.3 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | FastAPI（异步）+ Python 3.11 | 原生支持 SSE 流式；异步高并发 |
| 数据库 | SQLite（SQLAlchemy 兼容写法） | 演示级零运维，预留平滑迁移 PostgreSQL |
| 向量检索 | FAISS（内积索引）+ jieba bigram 嵌入 | 本地运行无外部依赖；接口与真实 embedding API 一致 |
| 关键词检索 | rank_bm25（BM25Okapi） | 专有名词/数字精确命中，与向量互补 |
| LLM | OpenAI 兼容协议（DeepSeek/智谱可换） | 国产模型合规、成本低、可替换 |
| 前端 | 原生 HTML/JS（聊天页）+ 服务端渲染（后台） | 无构建链，课程项目可维护性最高 |
| 鉴权 | JWT（HS256 自实现）+ PBKDF2 密码哈希 | 零第三方依赖，接口级角色校验 |

## 二、核心模块设计

### 2.1 RAG 检索管道（复用核心模块）

```
制度文档(md/pdf) → 解析 → 500字切片（按##标题分段，段内按句子边界聚合）
  → 切片入库 doc_chunks → 嵌入向量化 → FAISS 索引
检索：BM25 关键词分 + 向量语义分 → 归一化加权融合（向量 0.6 / BM25 0.4）→ top3
输出：片段 + 文件名 + 分数（回答末尾作为引用来源）
```

设计要点：切片按章节聚合保证语义完整；未配置 LLM 时降级为直接返回检索条文，系统永不不可用。

### 2.2 Agent 执行循环（智能体层）

- **循环**：模型决策 → 执行工具 → 结果回填 → 再决策，最多 5 轮，超限返回兜底话术；
- **工具集**（Function Calling）：

| 工具 | 类型 | 职责 |
|---|---|---|
| search_policy | 只读 | 检索学习支持制度条文 |
| query_resources | 只读 | 检索学习方法/课程 FAQ |
| check_schedule | 只读 | 时段冲突、每周 2 次限额、过去时段校验 |
| create_plan_draft | 写入(草稿) | 生成预约/计划草稿（须先通过校验） |
| submit_request | 写入(生效) | 提交草稿（须学生已确认） |

- **三层防线**（防跳过校验的核心设计）：
  1. 系统提示词约束（软引导，工具调用规则段不可编辑）；
  2. 编排层状态机（代码强制：create_plan_draft 前检查 schedule_valid，submit 前检查 student_confirmed，违规调用回填错误让模型自我纠正）；
  3. 数据层兜底（submit 内部复查草稿状态，杜绝脏数据）；
- **确认中断**：create_plan_draft 后强制暂停，草稿流式发给学生确认；Web 版通过"下一轮对话回复确认"实现，CLI 版为交互输入；
- **日志**：每轮工具名/参数/耗时/结果摘要写入 agent_logs 表，供评测与审计。

### 2.3 会话与消息（SSE 流式接口）

- `POST /api/chat`：事件流 session → status（"正在检索学习支持制度…"）→ delta（打字机）→ citations（引用来源）→ done；出错推送 error 事件（中文话术）；
- 每次请求携带最近 6 轮（12 条消息）历史作为上下文；
- 会话/消息落库，支持刷新页面历史回显；
- 心理危机类消息命中 high 风险规则时，强制在提示词中追加转人工指令。

### 2.4 管理后台

| 页面 | 功能 | 关键设计 |
|---|---|---|
| 仪表盘 | 文档/切片/会话/消息统计 | 一屏掌握系统运行状态 |
| 知识库管理 | md/pdf 上传→切片→入库→列表删除 | 删除后自动重建索引；类型限制与 5MB 限制 |
| 提示词模板 | 编辑系统提示词，存数据库立即生效 | 版本化记录；系统强制段（工具规则）不可编辑；可一键恢复默认 |
| 对话审计 | 按学生/时间筛选，风险红/黄标记 | 默认不展示完整原文（制度第九条）；管理员查看留痕 |

### 2.5 数据库设计（9 张表）

users（用户/JWT）、sessions（会话）、messages（消息+引用）、policy_documents（制度文档）、doc_chunks（切片+向量位置）、support_requests（预约/计划草稿，状态 draft→confirmed/cancelled）、agent_logs（工具轨迹）、system_prompts（提示词版本）、risk_rules（风险规则）。

### 2.6 安全设计

- 鉴权：JWT 24h 有效期；require_student / require_admin 接口级依赖；越权返回 4012/4013；
- 密码：PBKDF2-SHA256（10 万次迭代+盐）；JWT 密钥与 API Key 仅存 .env；
- 限流：单用户 6 次/分钟（4293 错误码）；
- 审计合规：审计页只展示风险片段与统计；对话保留一学年自动脱敏归档；
- 隐私制度呼应：辅导记录仅本人与辅导教师可查看（制度第九条）。

## 三、接口清单

| 接口 | 方法 | 角色 | 说明 |
|---|---|---|---|
| /api/auth/login | POST | 公开 | 登录返回 JWT |
| /api/chat | POST(SSE) | 学生 | 流式问答（五种事件） |
| /api/sessions、/api/sessions/{id}/messages | GET | 学生 | 会话列表/历史回显 |
| /api/admin/stats | GET | 管理员 | 仪表盘统计 |
| /api/admin/kb/upload、list、{id} | POST/GET/DELETE | 管理员 | 知识库管理 |
| /api/admin/prompt（GET/PUT/reset） | GET/PUT/POST | 管理员 | 提示词管理 |
| /api/admin/audit | GET | 管理员 | 对话审计 |
| /api/health | GET | 公开 | 健康检查 |

统一错误码：0 成功 / 4001 参数 / 4003 无权 / 4011 未登录 / 4012 需管理员 / 4013 学生不可访问 / 4004 文件不支持 / 4293 限流 / 5001 LLM 失败 / 5002 检索异常 / 5003 解析失败。

## 四、质量保障与交付

- **评测**：30 条评测用例（制度 10 含陷阱 3、工具调用 10、超范围/风险 5、多轮 5），上线判定通过率 ≥90% 且陷阱/风险类 100%；
- **上线检查**：25 项清单（数据安全/并发限流/异常兜底/内容安全/回滚，各 5 项，标注负责人/验证方法/通过标准）；
- **CI**：GitHub Actions 推送自动跑 pytest；
- **回滚**：分阶段 git 提交可回溯，rollback 5 分钟内完成，数据向后兼容。
